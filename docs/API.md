# API Payloads

Base URL: `http://localhost:3000/api`

All request bodies are JSON (`Content-Type: application/json`, max 10 KB).
Validation is strict: **unknown fields, wrong types, or bad formats are rejected with `400`**. Nothing is silently dropped or coerced.

- **IDs** are auto-increment integers (`1`, `2`, ...) generated by the server. Send them as JSON numbers in bodies (`"walletId": 1`, not `"1"`).
- **Amounts** are integers in minor units (agorot/cents): `1000` = 10.00 ILS. Decimals like `10.5` and strings like `"100"` are rejected.
- **Currency** is a 3-letter code (`ILS`, `USD`, …). Lowercase is accepted and stored in uppercase.

---

## Merchants

### `POST /merchants` - create a merchant

```json
{
  "name": "Coffee Shop"
}
```

| Field | Type | Required | Rules |
|---|---|---|---|
| `name` | string | yes | 1-200 chars, trimmed |

New merchants start as `ACTIVE`. Response `201`:

```json
{
  "id": 1,
  "name": "Coffee Shop",
  "status": "ACTIVE",
  "createdAt": "2026-10-25 09:01:07",
  "updatedAt": "2026-10-25 09:01:07"
}
```

### `PATCH /merchants/:id/status` - activate / deactivate

```json
{
  "status": "INACTIVE"
}
```

| Field | Type | Required | Rules |
|---|---|---|---|
| `status` | string | yes | `ACTIVE` or `INACTIVE` |

Response `200` with the updated merchant. An inactive merchant can't have approved charges or refunds.

## Wallets

### `POST /wallets` - create a wallet

```json
{
  "merchantId": 1,
  "currency": "ILS",
  "initialBalance": 1000
}
```

| Field | Type | Required | Rules |
|---|---|---|---|
| `merchantId` | integer | yes | must be an existing merchant (else `404`) |
| `currency` | string | yes | 3 letters |
| `initialBalance` | integer | no | ≥ 0, minor units, default `0` |

New wallets start as `ACTIVE`. Response `201`:

```json
{
  "id": 1,
  "merchantId": 1,
  "currency": "ILS",
  "balance": 1000,
  "status": "ACTIVE",
  "createdAt": "2026-10-25 09:01:07",
  "updatedAt": "2026-10-25 09:01:07"
}
```

### `PATCH /wallets/:id/status` - activate / deactivate

```json
{
  "status": "INACTIVE"
}
```

Same rules as the merchant status. An inactive wallet can't have approved charges or refunds.

## Transactions

Both POSTs below **require an `Idempotency-Key` header**: 1-255 chars of letters, digits, `.` `_` `:` `-` (a UUID works well).
Generate a new key per operation and **reuse the same key when retrying** that operation.

| Situation | Result |
|---|---|
| New key | `201`, transaction created |
| Same key + same body (retry) | `200` + header `Idempotent-Replayed: true`, the original transaction; money is **not** moved again |
| Same key + different body | `409 CONFLICT` |

Keys are scoped per merchant.

### `POST /transactions/charge` - charge a wallet

```
Idempotency-Key: 7f1c2a9e-1b2c-4d3e-8f90-123456789abc
```

```json
{
  "walletId": 1,
  "merchantId": 1,
  "amount": 400,
  "currency": "ILS"
}
```

| Field | Type | Required | Rules |
|---|---|---|---|
| `walletId` | integer | yes | must exist (else `404`) |
| `merchantId` | integer | yes | must exist (else `404`) |
| `amount` | integer | yes | > 0, minor units |
| `currency` | string | yes | 3 letters, must match the wallet's currency |

### `POST /transactions/refund` - refund a charge (full or partial)

```
Idempotency-Key: 5d0e8b3a-refund-1
```

```json
{
  "originalTransactionId": 1,
  "amount": 100
}
```

| Field | Type | Required | Rules |
|---|---|---|---|
| `originalTransactionId` | integer | yes | must be an **approved charge** (`404` if missing, `422` otherwise) |
| `amount` | integer | yes | > 0; all approved refunds together can't exceed the original charge |

Wallet, merchant and currency are taken from the original charge. You can refund one charge several times (partial refunds).

### Transaction response

Approved: `201` with the transaction (or `200` + `Idempotent-Replayed: true` on a retry).

Declined: the transaction is still saved (`status: DECLINED`) but **no money moves**, and the response is `422` with the reason as the error `code`, plus the saved transaction. Retrying the same key returns the same `422`.

```json
{
  "error": { "code": "INSUFFICIENT_FUNDS", "message": "Wallet 1 has insufficient funds for a 400 ILS charge" },
  "transaction": { "id": 4, "status": "DECLINED", "declineReason": "INSUFFICIENT_FUNDS", "...": "..." }
}
```

Approved example:

```json
{
  "id": 1,
  "walletId": 1,
  "merchantId": 1,
  "type": "CHARGE",
  "amount": 400,
  "currency": "ILS",
  "status": "APPROVED",
  "declineReason": null,
  "originalTransactionId": null,
  "clientRequestId": "7f1c2a9e-1b2c-4d3e-8f90-123456789abc",
  "createdAt": "2026-10-25 09:01:07",
  "updatedAt": "2026-10-25 09:01:07"
}
```

| `declineReason` | When |
|---|---|
| `WALLET_INACTIVE` | wallet status is `INACTIVE` |
| `MERCHANT_INACTIVE` | merchant status is `INACTIVE` |
| `WALLET_MERCHANT_MISMATCH` | the wallet belongs to a different merchant than `merchantId` |
| `CURRENCY_MISMATCH` | charge currency ≠ wallet currency |
| `INSUFFICIENT_FUNDS` | charge amount > wallet balance |
| `REFUND_EXCEEDS_ORIGINAL` | refund would bring total refunds above the charge amount |

## GET endpoints (no body)

| Endpoint | Query filters (all optional) |
|---|---|
| `GET /wallets/:id` | |
| `GET /wallets` | `status`, `merchantId`, `currency` |
| `GET /merchants/:id` | |
| `GET /merchants` | `status` |
| `GET /transactions/:id` | |
| `GET /transactions` | `walletId`, `merchantId`, `type` (`CHARGE`/`REFUND`), `status` (`APPROVED`/`DECLINED`) |

List endpoints return a plain JSON array, newest first.

## Errors

```json
{
  "error": {
    "code": "VALIDATION_ERROR",
    "message": "Request validation failed",
    "details": [
      { "path": "body.amount", "message": "amount must be an integer in minor units" },
      { "path": "body", "message": "Unrecognized key: \"isAdmin\"" }
    ]
  }
}
```

| Status | `code` | Meaning |
|---|---|---|
| 400 | `VALIDATION_ERROR` | invalid body / params / query / Idempotency-Key (see `details`) |
| 400 | `BAD_REQUEST` | body is not valid JSON |
| 404 | `NOT_FOUND` | wallet / merchant / transaction / route doesn't exist |
| 409 | `CONFLICT` | Idempotency-Key reused with a different body |
| 413 | `PAYLOAD_TOO_LARGE` | body over 10 KB |
| 422 | `UNPROCESSABLE` | refund target isn't an approved charge |
| 422 | a decline reason (`INSUFFICIENT_FUNDS`, `WALLET_INACTIVE`, `MERCHANT_INACTIVE`, `CURRENCY_MISMATCH`, `WALLET_MERCHANT_MISMATCH`, `REFUND_EXCEEDS_ORIGINAL`) | business rule failed; see Transactions |

## Quick start (curl)

```bash
API=http://localhost:3000/api

curl -X POST $API/merchants -H 'Content-Type: application/json' -d '{"name":"Coffee Shop"}'

curl -X POST $API/wallets -H 'Content-Type: application/json' \
  -d '{"merchantId":1,"currency":"ILS","initialBalance":1000}'

curl -X POST $API/transactions/charge -H 'Content-Type: application/json' \
  -H "Idempotency-Key: $(uuidgen)" \
  -d '{"walletId":1,"merchantId":1,"amount":400,"currency":"ILS"}'

curl -X POST $API/transactions/refund -H 'Content-Type: application/json' \
  -H "Idempotency-Key: $(uuidgen)" \
  -d '{"originalTransactionId":1,"amount":100}'
```
